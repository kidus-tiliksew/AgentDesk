# Testing the installer

`component-installer` §Verification governs this file.

## Automated tests

`pnpm --filter agentdesk test` runs the Vitest project `installer`, and root `pnpm check` runs it with every other package. The tests need Node 22, `sh`, and `curl`; the one test that runs `install.sh` in a pseudo-terminal also needs `python3` and is skipped without it. They need no Bun, no npm, no network, no real harness, and no real harness configuration.

Several tests make a file unreadable with `chmod 000` and are skipped for root. A process that holds `CAP_DAC_READ_SEARCH` reads such a file anyway, so those tests fail; some sandboxes grant that capability as an ambient capability to every process. Check `CapEff` in `/proc/self/status`, and when it is not zero, run the suite without the capability: `setpriv --ambient-caps=-all --inh-caps=-all -- pnpm run check`. The suite expects umask 022. Under umask 077, `skill.test.ts` "writes the Claude Code and Codex skills and no Cursor skill when both are installed" fails on the base as well, because it expects a skill file mode of 0644.

The tests use temporary home directories, a fake `PATH` holding stub `claude`, `codex`, `cursor-agent`, and `agy` executables that record their arguments (`test/fixtures/fake-harness.mjs`), and an in-process fake gateway that follows `component-gateway` §Sign-in endpoints. The stub `codex app-server` derives each `SessionStart` and `Stop` hook's key, hash, and trust from the sandbox's `hooks.json` and `config.toml`; its hash covers the event and the handler, never the position. The fake gateway also follows overlay-install-keys §Gateway for `POST /device/enroll`, and answers `GET /device/connection` with the token's `connection_id` and `harness`, as the gateway does. The tests prove the installer's side of the protocol, not a live sign-in or a live enrollment, not that T3 Code's `antigravity-acp` reads a profile's files, not that the compiled binary reads `--key-file -` from a real pipe, not that a harness loads the guidance, not that a live child agent obeys the child guidance, and not that a harness runs the resume hooks or resumes a session; only the manual checks below cover that. `test/resume/` covers what the resume hook commands do once they run (`component-resume` §Verification). One test in `test/resume/antigravity-hook.test.ts` writes a transcript of about 261 MiB to the system temporary directory, to check that the Antigravity stop hook reads past the first 256 MiB, and removes it afterwards. The suite needs that much free space there.

## Building

```sh
AGENTDESK_SERVER_ORIGIN=https://agentdesk.example pnpm --filter agentdesk build
AGENTDESK_SERVER_ORIGIN=https://agentdesk.example pnpm --filter agentdesk build:binaries
```

`AGENTDESK_SERVER_ORIGIN` is required and becomes the default server. `build` writes `dist/agentdesk.mjs`, the bundle with the skill and the guidance embedded. `build:binaries` also needs Bun, compiles that bundle, and writes `agentdesk-darwin-arm64`, `agentdesk-darwin-x64`, `agentdesk-linux-x64`, `agentdesk-linux-arm64`, and `SHA256SUMS` to `dist/release/`. The installer is not published to npm (DEC-10).

## Manual check before each release

Run this on a macOS machine and on a Linux host reached over SSH with no display. Use a release candidate's binaries and its deployed gateway. Record the date, the release tag, each host, each harness version, and the result of each step. A step not run stays unverified; the automated tests do not stand in for it.

1. Run `curl -fsSL https://agentdesk.kidus.sh/install | sh`. Confirm the script names the binary for the host, verifies the checksum, installs `~/.local/bin/agentdesk`, prints a `PATH` hint when that directory is not on `PATH`, and then starts the installer with no second command.
2. With Claude Code, Codex, Cursor, Antigravity (`agy`), and T3 Code with at least two Antigravity profiles under `${T3CODE_HOME:-~/.t3}/userdata/providers/antigravity` installed, confirm the installer lists all four harnesses as selected, that no browser opens, and that the prompt reads your answer from the terminal. On macOS this is the check that the compiled binary can read the terminal device `install.sh` gives it; the automated tests run no Bun binary.
3. Enter the printed `XXXX-XXXX` code in the AgentDesk app under Add machine. Confirm the app shows the host name and the four harnesses, then approve. Confirm the installer finishes within 10 seconds of approval, prints no token, and ends by telling you to start a new agent session.
4. Confirm `~/.claude.json`, `${CODEX_HOME:-~/.codex}/config.toml`, `~/.cursor/mcp.json`, and `~/.gemini/config/mcp_config.json` hold the `agentdesk` entry; that `~/.gemini/config/hooks.json` holds the named hook `agentdesk` whose `SessionStart` holds one handler running `~/.local/bin/agentdesk context --harness antigravity` with `"timeout": 30` and whose `Stop` holds one handler running `~/.local/bin/agentdesk hook stop --harness antigravity` with `"timeout": 3600`, beside any other named hooks; that each T3 Code profile's `config/mcp_config.json` holds the same `agentdesk` entry as `~/.gemini/config/mcp_config.json` and its `config/hooks.json` the same named hook `agentdesk`, beside any other entries; that `~/.gemini/config/skills/agentdesk/SKILL.md` exists and each profile's `config/skills` is still T3 Code's link to `~/.gemini/config/skills`, with no AgentDesk file written inside it; that `~/.claude/settings.json`, `${CODEX_HOME:-~/.codex}/hooks.json`, and `~/.cursor/hooks.json` hold the hook running `~/.local/bin/agentdesk context --harness <id>`; that Codex's `hooks.json` holds a `Stop` group running `~/.local/bin/agentdesk hook stop --harness codex` with `"timeout": 10`; that Cursor's `hooks.json` holds an `afterMCPExecution` entry running `~/.local/bin/agentdesk hook after-mcp --harness cursor` and a `stop` entry running `~/.local/bin/agentdesk hook stop --harness cursor` with `"timeout": 3600` and `"loop_limit": null`; that `~/.claude/settings.json` holds no resume hook; that `config.toml` holds a `[hooks.state."<key>"]` table for the session-start hook and one for the `Stop` hook; that unrelated entries are unchanged; that CLAUDE.md and AGENTS.md are unchanged; and that `~/.config/agentdesk/state.json` has mode 0600 and holds no token.
5. In a new directory with no AgentDesk file, start a new session of each harness. Before sending a message, confirm the agent's context holds the guidance (ask the agent what it knows about AgentDesk). In Codex, confirm `/hooks` lists both AgentDesk hooks as trusted and that `codex exec` runs them. In Antigravity, start a new `agy` conversation and confirm the guidance is in its context with no trust step, and that `agy` lists the `agentdesk` MCP server as connected. In T3 Code, start a new Antigravity thread in each profile and confirm the same: the guidance is in its context with no trust step, and the agent can call the `agentdesk` tools. Start one T3 Code Antigravity thread with `AGENTDESK_PARENT_SESSION` set for that launch only and confirm it starts with the child guidance. Have the agent call `ask` and confirm each decision reaches the phone.
6. In Claude Code and Codex, run `/compact` (and `/clear`) and confirm the guidance is in the context again afterwards.
7. Run `curl -fsSL https://agentdesk.kidus.sh/install | sh -s -- --only codex`. Confirm only Codex is handled, no code is shown, and the connection keeps working.
8. Run `agentdesk install` again. Confirm no code is shown, every connection keeps working, and the hooks and Codex trust are unchanged. Then create a new Antigravity profile in T3 Code, run `agentdesk status` and confirm it reports the profile as not set up, run `agentdesk install`, and confirm no code is shown and the new profile gets the entry and the hooks.
9. Revoke one connection in the app, then run `agentdesk install` again. Confirm a code is shown only for that harness.
10. Run `agentdesk status`. Confirm each harness shows its connection check, skill version, and session-start hook, with no trust for Antigravity; that Codex and Antigravity also show their `Stop` hook and Cursor its `afterMCPExecution` and `stop` hooks; that each T3 Code profile shows its MCP entry matching `~/.gemini/config/mcp_config.json` and both hooks; and that each Codex hook shows `trust trusted`.
11. Revoke one connection in the app, run `agentdesk install` again, and decline in the app. Confirm the installer exits with status 1 and prints "Sign-in was declined in the app".
12. Delete the `agentdesk` entry from one harness configuration other than Antigravity by hand and run `agentdesk uninstall`. ## Live resume check before each release

`component-resume` §Verification names this check; the automated tests do not stand in for it. Run it after step 5 above, with the release candidate installed by `install.sh`, in six sessions: Claude Code, Codex under the default `workspace-write` sandbox, Codex in a thread hosted by T3 Code, the Cursor CLI (`cursor-agent`), the Antigravity CLI (`agy`), and Antigravity in a thread hosted by T3 Code. Use a repository with no AgentDesk file.

For each session:

1. Ask the agent to ask you a confirm question through AgentDesk and then end its turn. Confirm the question appears in chat and on the phone, and that the turn ends without the agent waiting on the answer.
2. Answer the question in the AgentDesk app on the phone. Record the time of the answer.
3. Confirm a new agent turn starts within 60 seconds of the answer, with no message typed in the session. Record the time the turn starts. Confirm the agent's first message states the answer and that it came from the phone (`req-installation-and-agent-guidance` AC-12.8).
4. Have the agent ask a second question, then answer it in the chat instead of on the phone. Confirm the agent relays the answer through AgentDesk and that no further turn starts after the session goes idle; wait at least 60 seconds.

In each Antigravity session, the CLI and the T3 Code thread, the `Stop` hook holds the agent's loop while the decision is pending (`component-resume` §Antigravity stop hook), so also check:

5. Have the agent ask a third question and end its turn. Wait at least two minutes, so the hook is holding, then answer on the phone. Confirm a new turn starts within 60 seconds of the answer and that its first message states the answer and that it came from the phone. Record the time the turn ended, the answer time, and the time the turn starts. The hook accepts an `ask` result only from a step whose `type` is `GENERIC` right after the agent's `PLANNER_RESPONSE` step that holds the `ask` call, with the content ending in `{"decision_id": ..., "state": "pending"}`. When no turn starts, record the key names, the `type` values, and the `step_index` values of those two lines in `transcript_full.jsonl`, without their text.
6. Have the agent ask a fourth question and end its turn. While the hook holds, type a chat message that does not answer the question, such as "what time is it?". Record whether `agy` shows the message at once, queues it until the hook returns, or drops it, and record when the agent answers it. Then answer the question on the phone, and confirm exactly one new turn starts for the answer. Record each time.
7. Have the agent ask a fifth question and end its turn. While the hook holds, type the answer in the chat. Record when the message reaches the agent and when the hook returns. Once the agent relays the answer through AgentDesk, confirm that no continuation follows for that decision and that no further turn starts after the session goes idle; wait at least 60 seconds.
8. Have the agent ask a sixth question, end its turn, and leave it unanswered. Confirm the hook returns about 50 minutes after the turn ended and the session goes idle with no new turn. Record both times.
9. Have the agent ask a seventh question with a reversible default and a deadline 10 minutes away, then end its turn. Leave it unanswered on every surface. When the deadline passes, confirm the app shows the default applied. Confirm a new turn starts within 60 seconds of the expiry (`req-installation-and-agent-guidance` AC-12.2, AC-12.9). Confirm its first message states the default answer and that the deadline applied it. Record the time the turn ended, the deadline, the expiry time the app shows, and the time the turn starts.
10. Have the agent ask an eighth question and end its turn. Leave it unanswered until 45 minutes after the turn ended, late in the 50-minute hold, then answer on the phone. Confirm a new turn starts within 60 seconds of the answer and that its first message states the answer and that it came from the phone (AC-12.1, AC-12.9). Record the time the turn ended, the answer time, and the time the turn starts.
11. Have the agent ask a ninth question with a reversible default and a deadline 45 minutes away, then end its turn. Leave it unanswered. Confirm a new turn starts within 60 seconds of the expiry and that its first message states the default answer and that the deadline applied it (AC-12.2, AC-12.9). Record the time the turn ended, the expiry time, and the time the turn starts.

Record, for each session: the date; the release tag; the host; the harness version (`claude --version`, `codex --version`, the T3 Code version, `cursor-agent --version`, `agy --version`, and for the T3 Code Antigravity thread both the T3 Code version and the `antigravity-acp` version); for Codex, the sandbox mode; the answer time and the resumed turn's start time from step 3, and their difference; for each Antigravity session, the CLI and the T3 Code thread, the times and observations from steps 5 to 11, with the difference between each answer or expiry and the turn it started; the result of each step; and any step not run. A step not run, or a session not checked, is recorded as unverified, never as passed. The fake clock in `test/resume/antigravity-hook.test.ts` does not certify how `agy` behaves during a hold.
